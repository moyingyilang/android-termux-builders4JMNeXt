# 在 Termux + 容器环境里做构建提速：方法与实测

这份文档只讲两件事：**怎么把"快了多少"测准**，以及**在本机这类环境下哪些"优化"其实无效**。
（环境：aarch64 Android + Termux + chroot；CPU governor 被内核锁住无法 boost；温度常年在 90 度以上。）

## 一、先量后改：受控 A/B 方法

一条命令跑一次、看时间变没变，是**测不出结论**的 —— 耗时里混着热状态、缓存冷热、后台残留进程。
可用的做法：

| 要素 | 做法 |
| --- | --- |
| 固定场景 | 每次先改一行源码（追加一个标记注释），强制增量编译真正参与；否则测到的只是 UP-TO-DATE 的地板（本机约 1 秒） |
| 交替顺序 | A/B/A/B，而不是 A/A/B/B —— 温度是单向漂移的 |
| 各两轮 | 单轮差异很可能就是噪声 |
| 结果立即落盘 | 每轮计时**追加写入文件**。只放在屏幕输出里，一旦读取中断就全丢（踩过） |
| 判定事先写死 | 开测前写下"什么算采纳"，避免事后替数据找理由 |
| 收尾清痕 | 跑完删掉标记行，`git status` 必须干净 |

## 二、本机实测：哪些"优化"其实无效

| 项 | 实测（受控 A/B） | 结论 |
| --- | --- | --- |
| `--no-daemon` | 21/14 秒；daemon 7/5 秒 | **不要用 `--no-daemon`**：每次多花 7-16 秒，daemon 首次启动只约 2 秒 |
| `org.gradle.workers.max=2` | 默认 17/20 秒；w=2 为 22/21 秒 | 默认更快，**不设**（并发越高越早热降频） |
| `org.gradle.parallel=true` | 串行 20/24 秒；并行 24/21 秒 | 差异落在噪声内，**不设** |
| 跨会话保留 daemon | 进程随容器会话消失 | 机制上不可能，不是配置问题 |
| **多件事合并进同一次会话** | 4 件事 34 秒（分批调用需 60 秒以上） | **有效**，这是本机最大的确定性收益 |

**被作废的两次测量**（都曾看起来很美）：`workers=2 快一倍`、`--no-daemon 更快`。
前者不可复现，后者被反向证实。启示：**参数类"优化"必须有受控复测才敢留**。

## 三、打包链的耗时画像（单会话 7 步，合计 433 秒）

gradle 构建 13 秒 + Linux aarch64 四件套 84 秒 + **Linux x86_64 四件套 170 秒（含 qemu 跑 x86_64 rpmbuild）**
+ Windows 两个 ZIP 69 秒 + 两个单体 exe 97 秒。

提速方向是**减少重复工作**（输入未变就跳过），而不是调 Gradle 参数。

## 四、想做"输入未变就跳过"的闸门？四条硬约束

1. **输入必须是真输入**：不能用脚本自己生成的中间物（`$STAGE`）——那会让指纹永远不变 → 产物永不更新且**不报错**；
   也不能用脚本会重新生成的文件（fat jar）——那会让指纹每次都变 → 闸门永不生效。
2. **接线位置在版本变量定义之后**：脚本多为 `set -euo pipefail`，在 `VERSION=` 之前引用它 →
   `unbound variable` 直接退出。
3. **指纹算法**：`find "$dir" -type f -printf '%p %s %T@\n' | LC_ALL=C sort | sha256sum` ——
   实测"未改动 → 指纹相同、touch → 指纹不同"两个方向都成立。
   **不要**用 `stat -c %Y`（只到秒，同一秒内 touch 检测不到）。
4. **安全兜底**：产物清单为空、指纹为空、或任一产物不存在 → **一律不跳过**（宁可多跑，绝不漏更）；
   并提供 `FORCE=1` 强制重跑。

> 状态：本文档记录的四条约束来自两次失败尝试（接线后被改坏的输入与位置问题）。
> **闸门本身尚未在本项目接线** —— 已回退，原因是集成后脚本早期退出、根因未查明。
> 在"输入变了必须不跳过"这条被自动化验收证明之前，不要接线。

## 五、环境限制（记录在案，避免反复试错）

- CPU governor 被锁：写 `/sys/.../scaling_governor` 即使 root 也被拒；无法 boost；
- 温度常年 93 度上下（红线 105）：并发越高越容易热降频，所以"少并发"有时更快；
- `/proc/meminfo` 在 Termux 下不可读：内存只能定性；
- `/tmp` 在 Termux 侧**不可写**：中间文件一律放项目外的 `.work/`（踩过：往 `/tmp` 写失败会导致
  `awk > /tmp/x` 静默失败，后续"删除旧内容但没插入新内容"，把脚本改坏）。

## 六、按需打包闸门的实测效果（与实现要点）

同一项目、同一环境，整条链跑两轮：

| 轮次 | gradle | Linux aarch64 | Linux x86_64 | 两个 ZIP | 两个 exe | 合计 |
| --- | --- | --- | --- | --- | --- | --- |
| 第 1 次 | 28 秒 | 0 | 233 秒 | 31 / 35 秒 | 13（失败）/ 49 秒 | **389 秒** |
| 第 2 次 | 22 秒 | 0 | 0 | 0 / 0 | 61（补跑）/ 0 | **84 秒** |

实现只有两个函数（`gate_begin` / `gate_commit`）+ 每个平台脚本一行调用；指纹文件放在发行目录里。
**注意**：它只省"输入未变"的重跑；一旦改了源码，平台打包仍会（也必须）全量重做。

参考实现与四条硬约束见上文第四节。建议把这个模式用在任何"多平台、多步骤、每步几分钟"的打包链上。
